# Target: GitHub

> Repository README, documentation, and share-preview rules for Vibe-to-UI. Use the shared brand master and tokens; this target only adapts their application.

- **Slug**: `github`
- **Updated**: 2026-07-13
- **Status**: active

## Medium identity

- **Human name**: GitHub repository and README
- **Artifact this produces**: Repository README, documentation visuals, social-preview art, and contribution-facing examples.
- **One-liner**: Give developers a fast, credible path from “what is this?” to “how do I use it?” without losing the brand's authored feeling.

## Format constraints

- README banner: work at 1600 × 800 px; reserve the central 76% width and 60% height for any slogan or key type.
- README: optimize for GitHub's narrow content column, light/dark page chrome, selectable text, and copyable commands.
- Social preview: make a separately composed image for its target ratio; do not blindly crop the README banner.

## Audience & context

- **Where it is seen**: Repository landing page, documentation links, issue/contribution flow, and link previews.
- **Reading distance**: Desktop-first scanning with mobile fallback; readers decide in seconds whether the project is useful and trustworthy.

## Brand application

- **Color**: Let the banner carry the Dusty Pink / Ink Black / Cool White field; use Electric Blue only for a live-state marker or key action cue. Markdown body stays calm and high contrast.
- **Type**: One strong display statement in an image at most; all setup, capability, and decision content remains selectable Markdown text. Mono is reserved for commands, paths, and labels.
- **Imagery**: Product UI excerpts, a restrained system diagram, or one brand banner. Never use a decorative collage that obscures the installation path.
- **Motion (if any)**: None required. Use static captures and diagrams that remain clear in image previews.

## Hierarchy budget

- **Must appear**: Product one-liner, quick-start path, profile → target → handoff workflow, examples, contribution/license links.
- **Must not crowd the first view**: Multiple large badges, simulated UI controls, lengthy narrative copy, or more than one central visual.

## Production limits

- Prefer compressed PNG/WebP for diagrams and banner imagery; write useful alt text.
- Code blocks should be real text, never embedded in an image.
- Verify screenshots in GitHub light and dark contexts; avoid relying on a white page background.

## Do / don't

- **Do**: Lead with usefulness, then make the visual language recognizable; keep sections compact and easy to link.
- **Don't**: Turn the README into a landing-page mockup, use fake buttons, hide meaningful instructions inside art, or introduce another token palette.

## Notes

- The slogan may appear in the banner as: *Build the dream you were told to put away.* Keep the sentence in surrounding Markdown as accessible text when it is central to the message.
